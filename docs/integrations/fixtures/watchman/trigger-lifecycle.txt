$ ["trigger", <root>, {same name, expression changed to ["match","*.md"]}]
{"version":"2026.07.27.00","disposition":"replaced","triggerid":"jjukkumi-e0t5"}
exit=0
(Re-adding an existing trigger name with a different definition reports disposition
"replaced" and resets the trigger's incremental position: the next execution delivers a
full fresh list without WATCHMAN_SINCE, exactly like a first installation. Re-adding the
identical normalized definition reports disposition "already_defined" and preserves the
position: the next execution stays incremental with WATCHMAN_SINCE set, so an identical
install is a true no-op; see trigger-payload-after-idempotent-reinstall.json.)
